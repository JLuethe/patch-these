### 1Password

**Incident · Mitigate · My computer**

On November 19, 2026, 1Password began investigating indications that an attacker gained access to an employee's corporate GitHub account. The actor used the account to access source code and push malicious code to backend services, which downloaded administrative data. The downloaded account records for a subset of users include names and email addresses; account and user identifiers, and account creation and last sign-in times; public keys, which are public by design; Secure Remote Password protocol parameters, which cannot be used to access the account; tokens present in emailed links for invitations, provisioning, and account recovery; and other non-secret account metadata such as version numeric identifiers and file numeric identifiers. The attacker also copied source code from private repositories and gained access to the CI/CD system. 1Password says that source code is not customer data and contains no user secrets, that CI/CD contains infrastructure-related secrets, and that those credentials were rotated, with no impact to services, availability, or product security. Vaults and the items in them, the keys that protect the vaults, the account password, the Secret Key, account recovery keys, and the apps and browser extensions were not accessed. A small number of users with a provisioning-invite or account-recovery token were specifically notified. The token cannot access the account by itself; it works only together with an SSO sign-in or a code sent to the registered email address. 1Password expanded that code from six numeric digits to ten alphanumeric digits. There is no CVE.

**What to do:** You do not need to update anything in your 1Password account. Be cautious about phishing attempts in the form of unexpected emails, texts, or calls that mention 1Password, invitations, or account recovery. 1Password will never ask for your account password or Secret Key. Only enter them in the official 1Password app or on the official website, and only when you opened the app or typed the address yourself. The Secret Key is only needed the first time you sign in on a new device or browser. Keep your Secret Key and account password safe. If you see something suspicious, tell 1Password at support@1password.com.

**Why:** 1Password confirmed that an attacker copied account records for a subset of customers, including invitation and recovery tokens. 1Password says customers do not need to change the account, and the remaining customer step is to watch for phishing.

**Applies to:** A subset of 1Password customers. Copied records include names and email addresses; account and user identifiers, account creation and last sign-in times; public keys; Secure Remote Password protocol parameters; tokens in emailed links for invitations, provisioning, and account recovery; and other non-secret account metadata. The attacker also copied source code from private repositories and gained access to CI/CD. Vaults, the items in them, the keys that protect the vaults, the account password, the Secret Key, account recovery keys, and the apps and browser extensions were not accessed.

**Exploitation:** confirmed.

### Todoist

**Incident · Rotate credentials · My computer**

Todoist says that between November 22 and 23, an attacker used a stolen credential associated with its version control system to modify automated workflows in three repositories and obtain additional credentials, then took over an employee's work account and reached its cloud infrastructure. On November 23, 2026, the attacker gained unauthorized access to production systems and retrieved some customer information. Todoist says it blocked the access paths, revoked and replaced exposed internal credentials, protected affected accounts, and emailed affected customers. How the first credential was obtained has not been established. There is no CVE.

**What to do:** Follow the instructions in the email Todoist sent you; if you did not receive one, Todoist says there is nothing to do. Depending on your case: 1. If your password was disabled, reset it and choose a new password, not your old Todoist password or one you use elsewhere. 2. If you reused your Todoist password elsewhere, change it on those services too. 3. If your Slack integration was disconnected, reconnect it. 4. If you used the Todoist for Outlook add-in, reconnect it. 5. If you used a Todoist API token in scripts or services, update them with your new token. 6. If you stored API keys, access tokens, recovery phrases, or other credentials in Todoist content, revoke and replace them with the relevant service. 7. If your content included shared links that let anyone with the link access a file, restrict access or replace those links. Todoist's notification comes from no-reply@notify.todoist.com; watch for fake emails.

**Why:** Todoist confirmed that an attacker retrieved customer information on November 23, 2026, and affected customers have account-specific steps to take.

The attacker could also read source code; Todoist found no changes to application code.
