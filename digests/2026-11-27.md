### Apache Roller

**Vulnerability · Update · Apps & servers**

Apache Roller has an unauthenticated deserialization flaw in its XML-RPC endpoint (CVE-2026-129448) that can let a remote attacker run arbitrary code. Apache rates it Critical, CVSS 9.8, and says it is being actively exploited. CISA added it to the KEV catalog on 2026-11-20. Turning off XML-RPC in the admin UI does not protect older versions.

**What to do:** Upgrade Apache Roller to 6.1.6 or later (6.1.7 is the current release). If you can't upgrade right away, apply Apache's interim mitigation below and restart Roller.

1. Upgrade to Apache Roller 6.1.6 or later from https://roller.apache.org/downloads/downloads.html.
2. If you cannot upgrade right away, set "enabledForExtensions" to "false" in WEB-INF/web.xml, or remove the "/roller-services/xmlrpc" servlet mapping, then restart Roller.
3. Do not rely on disabling XML-RPC in the administration UI; Apache says older versions deserialize the request before checking that setting.

**Why:** CVE-2026-129448 lets an unauthenticated remote attacker run code on Apache Roller through the XML-RPC endpoint; Apache says it is being actively exploited and CISA added it to KEV on 2026-11-20.

**Applies to:** Apache Roller 4.0.0 through 6.1.4 per the CVE record; Apache says this is the same flaw an earlier CVE listed for 6.1.5, so every release before 6.1.6 should be treated as affected.

**Verification notes:** The Roller 6.1.7 release notes were not opened, so it is unconfirmed whether 6.1.7 adds further security fixes; the action names 6.1.6, the fixed release in Apache's advisory. FIRST EPSS score dated 2026-11-27. Ransomware use is listed as Unknown in KEV.

### NoMachine Personal Edition for Windows

**Supply chain · Mitigate · Everyone & operators**

NoMachine says that during its security incident of 19 and 20 November 2026, the Personal Edition for Windows installer on its website was replaced by a tampered copy that adds a remote-access tool. That tool can run commands with administrator rights, read and change files, view the screen and reach other devices on the same network, and restarts itself every minute. NoMachine says the tampered file is unsigned, that the malware does not spread on its own, and that the safest fix is to reinstall Windows. A verified installer was restored on 20 November. There is no CVE.

**What to do:** If you downloaded and ran the NoMachine Personal Edition for Windows installer between 19 November 13:43 UTC and 20 November 10:00 UTC, treat that computer as fully exposed and follow NoMachine's steps, with reinstalling Windows as the safest fix.

1. Check for a python folder inside the NoMachine folder (normally C:\\Program Files\\NoMachine\\python), a running pythonw.exe in Task Manager, an installer with no embedded digital signature, or network connections to d137ukgg9ynlmn.cloudfront.net. Any one means the tampered installer was run.
2. If affected, disconnect the computer from the internet and do not type passwords on it.
3. From a different, clean device, change important passwords and turn on two-step verification.
4. Copy only personal files to a USB stick from the affected computer, then wipe it and reinstall Windows from clean media.
5. If you cannot reinstall right away, follow NoMachine's tested manual removal steps in its article while offline, then run a full antivirus scan.
6. Afterwards, change passwords again from a clean computer, including browser-saved passwords, saved NoMachine connection passwords and SSH keys kept on the affected computer, and reinstall NoMachine from the correct package.
7. If it was a work computer or held other people's data, tell your IT or security team.

**Why:** NoMachine confirms its Windows Personal Edition download was replaced for about 20 hours with a tampered installer that gives an attacker remote control of the computer.

**Applies to:** NoMachine says you may be affected if you downloaded nomachine-personal-edition\_10.2.3\_1\_x64.exe from its website between 19 November 2026 13:43 UTC and 20 November 2026 10:00 UTC and ran it on a Windows computer. macOS, Linux, other NoMachine products and automatic updates were not affected.

**Verification notes:** NoMachine's related software-update notice SU11X00294 was not read separately. The vendor article does not name the attacker or say how the download was replaced.

**Compromise:** confirmed.

### F5 BIG-IP and BIG-IQ (iControl SOAP)

**Vulnerability · Update · Apps & servers**

F5's CVE-2026-125274 lets an authenticated iControl SOAP user with at least Guest privileges inject an unauthorized management request, which F5 says may allow running arbitrary system commands, creating or deleting files, or disabling services. It is a control-plane issue only. F5 scores it CVSS 3.1 8.8 and CVSS 4.0 8.7. Exploitation was not established, and it was not in the CISA KEV catalog at this check.

**What to do:** Update BIG-IP to 21.1.0.3, 17.5.1.10 or 17.1.3.6 or later on your branch, and BIG-IQ to 8.4.2.3 or later. Until then, remove iControl SOAP access for users who are not fully trusted and restrict iControl SOAP to trusted networks.

1. Remove access to iControl SOAP for users who are not completely trusted; F5 says this is the only mitigation that applies while users still have access.
2. Block iControl SOAP access through self IP addresses: set Port Lockdown to Allow None for each self IP, or use Allow Custom and block the iControl SOAP port (TCP 443 by default, or your configured port). This can affect other services, including high availability.
3. Block iControl SOAP access through the management interface by restricting management access to trusted users and devices over a secure network.

**Why:** CVE-2026-125274 lets any authenticated iControl SOAP user with at least the Guest role run system commands on BIG-IP, and fixed releases are named in F5's CVE record; exploitation was not established.

**Applies to:** Per F5's CVE record: BIG-IP iControl SOAP 21.0.0 before 21.1.0.3, 17.5.0 before 17.5.1.10, and 17.1.0 before 17.1.3.6; BIG-IQ 8.4.0 before 8.4.2.3. Versions past End of Technical Support are not evaluated. F5 says this is a control-plane issue with no data-plane exposure.

**Verification notes:** F5 advisory K000163936 did not render, so fixed versions are taken from the affected ranges in F5's own CVE record and the newest BIG-IP release on each branch was not confirmed on F5's site.
