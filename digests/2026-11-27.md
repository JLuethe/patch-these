### RealVNC Viewer, Server, Connect, Classic Viewer and On-Demand Assist

**Vulnerability · Update · Everyone & operators**

RealVNC advisory RVNC-2026-001 (CVE-2026-137738) fixes a memory-safety flaw in UDP-based connections that could let an attacker run code remotely, as root on certain platforms, or crash the software before authentication. It affects both RealVNC Viewer and Server apps on desktop and mobile. RealVNC rates it Critical, CVSS 9.8, and says it is not aware of exploitation in the wild. The CVE was not in the CISA KEV catalog at this check.

**What to do:** Update RealVNC Viewer and the Connect app to 8.6.2 or later, Server to 7.19.1 or later, Classic Viewer to 7.18.3 or later, and On-Demand Assist to 3.5.0 or later; check that mobile Viewer and Server apps have updated (Viewer 4.9.6, Server iOS 2.8.2, Server Android 2.8.4 or later).

1. RealVNC Viewer, RealVNC Server and the RealVNC Connect app: download the latest version from https://www.realvnc.com/en/connect/download/ and install it on your devices.
2. RealVNC Classic Viewer: go to https://manage.realvnc.com, then Downloads, and download and install the latest version on your devices.
3. RealVNC On-Demand Assist: download the latest version from https://www.realvnc.help/en/ and advise end users to delete any older copies they downloaded.
4. Mobile apps should update automatically; to check, open RealVNC Viewer or RealVNC Server in Google Play or the App Store and tap Update.

**Why:** CVE-2026-137738 is a pre-authentication memory-safety flaw that RealVNC rates Critical, CVSS 9.8, with fixed releases for every affected app; RealVNC says it is not aware of exploitation.

**Applies to:** Desktop (Windows, macOS, Linux): RealVNC Viewer 8.4.0 to 8.6.1, Classic Viewer 6.4.0 to 7.18.2, Server 6.4.0 to 7.19.0, Connect app 8.6.1 and earlier, On-Demand Assist 3.4.1 and earlier. Mobile: Viewer iOS 3.7.0 to 4.9.5, Viewer Android 3.5.0 to 4.9.5, Server iOS 2.8.1 and earlier, Server Android 2.8.3 and earlier. RealVNC says cloud-hosted connectivity and manually configured direct connections (including offline licensed and on-premises deployments) are affected; TCP-only direct connections are not exposed.

### F5 BIG-IP and BIG-IQ (iControl SOAP)

**Vulnerability · Update · Apps & servers**

F5's CVE-2026-125274 lets an authenticated iControl SOAP user with at least Guest privileges inject an unauthorized management request, which F5 says may allow running arbitrary system commands, creating or deleting files, or disabling services. It is a control-plane issue only. F5 scores it CVSS 3.1 8.8 and CVSS 4.0 8.7. Exploitation was not established, and it was not in the CISA KEV catalog at this check.

**What to do:** Update BIG-IP to 21.1.0.3, 17.5.1.10 or 17.1.3.6 or later on your branch, and BIG-IQ to 8.4.2.3 or later. Until then, remove iControl SOAP access for users who are not fully trusted and restrict iControl SOAP to trusted networks.

1. Remove access to iControl SOAP for users who are not completely trusted; F5 says this is the only mitigation that applies while users still have access.
2. Block iControl SOAP access through self IP addresses: set Port Lockdown to Allow None for each self IP, or use Allow Custom and block the iControl SOAP port (TCP 443 by default, or your configured port). This can affect other services, including high availability.
3. Block iControl SOAP access through the management interface by restricting management access to trusted users and devices over a secure network.

**Why:** CVE-2026-125274 lets any authenticated iControl SOAP user with at least the Guest role run system commands on BIG-IP, and fixed releases are named in F5's CVE record; exploitation was not established.

**Applies to:** Per F5's CVE record: BIG-IP iControl SOAP 21.0.0 before 21.1.0.3, 17.5.0 before 17.5.1.10, and 17.1.0 before 17.1.3.6; BIG-IQ 8.4.0 before 8.4.2.3. Versions past End of Technical Support are not evaluated. F5 says this is a control-plane issue with no data-plane exposure.

**Verification notes:** F5 advisory K000163936 did not render, so fixed versions are taken from the affected ranges in F5's own CVE record and the newest BIG-IP release on each branch was not confirmed on F5's site.
