### React Server Components and Next.js

**Vulnerability · Update · Apps & servers**

A deserialization flaw in React Server Components (CVE-2026-126187) can lead to remote code execution from crafted payloads when a response carries multiple typed arrays and an attacker-controlled value. React says only rare cases are affected but recommends updating immediately; apps that don't use a server or an RSC-capable framework are not affected. Next.js published a matching advisory for \`use cache\` functions that return multiple typed arrays and says there is no workaround. The advisories date from October and November; posts on X on 28 Nov say proof-of-concept code and a test lab are now public, which we have not verified. No exploitation has been confirmed and it is not in CISA KEV.

**What to do:** Upgrade the react-server-dom packages to 19.0.9, 19.1.10, 19.2.9 or 19.3.1 or later in your line, and Next.js 16 apps to 16.4.1 or later (16.4.6 is the current release).

1. Check whether your app uses React Server Components through a framework or bundler plugin (react-server-dom-webpack, -parcel or -turbopack).
2. Upgrade those packages to 19.0.9, 19.1.10, 19.2.9 or 19.3.1 or later, matching your release line.
3. For Next.js 16.0.0 through 16.4.0, upgrade to 16.4.1 or later even if you don't have a \`use cache\` function returning typed arrays; Next.js lists no workaround.

**Why:** CVE-2026-126187 can let an unauthenticated remote attacker run code on servers using React Server Components in affected configurations; React rates it Critical (CVSS 4.0 9.5), and posts on 28 Nov say proof-of-concept code is now public.

**Applies to:** react-server-dom-webpack, react-server-dom-parcel and react-server-dom-turbopack 19.0.0 through 19.0.8, 19.1.0 through 19.1.9, 19.2.0 through 19.2.8, and 19.3.0. Next.js 16.0.0 through 16.4.0 apps using the App Router with Cache Components and a \`use cache\` function that returns multiple typed arrays (Next.js advisory GHSA-673q-mjm6-r5xr).

**Verification notes:** Public proof-of-concept is reported only by social posts and was not checked. Next.js releases after 16.4.1 were not reviewed for further security fixes. The Next.js advisory carries no CVE id; it is linked to CVE-2026-126187 by posts and its matching description, not by the advisory itself. FIRST EPSS dated 2026-11-27. CISA KEV catalogVersion 2026.11.27 checked.

### PHP (PHP-FPM)

**Vulnerability · Update · Apps & servers**

PHP can fail to discard unread request-body bytes before reusing a persistent PHP-FPM or LSAPI connection (CVE-2026-129289). When an app opens php://input without reading it to the end, an unauthenticated attacker can make the leftover bytes form a separate FastCGI request, bypass front-end routing and run attacker-controlled PHP code with the worker's privileges. It requires connection reuse between the web server and PHP-FPM. PHP fixed it on 19 Nov; a researcher's detailed write-up circulated on 28 Nov. No exploitation has been confirmed and it is not in CISA KEV.

**What to do:** Upgrade PHP to 8.2.36, 8.3.37, 8.4.28 or 8.5.13 or later and restart PHP-FPM.

1. Upgrade PHP to 8.2.36, 8.3.37, 8.4.28 or 8.5.13 or later in your release line (or your distribution's patched package), then restart PHP-FPM.
2. Check whether your web server reuses FastCGI connections to PHP-FPM (for example nginx \`fastcgi\_keep\_conn on\`); those setups are the ones exposed.

**Why:** CVE-2026-129289 can let an unauthenticated attacker run PHP code through PHP-FPM when the web server reuses FastCGI connections; PHP rates it Critical (CVSS 4.0 9.2), a detailed research write-up was published on 28 Nov, and its EPSS is 0.44.

**Applies to:** PHP before 8.2.36, 8.3.0 before 8.3.37, 8.4.0 before 8.4.28, and 8.5.0 before 8.5.13, when running under PHP-FPM (or LSAPI) with persistent backend connections (FCGI\_KEEP\_CONN).

**Verification notes:** The interim workaround of turning off FastCGI connection reuse comes from search summaries, not from the PHP advisory text we read, so it is left out of the steps. Later PHP releases were not reviewed for further security fixes. FIRST EPSS dated 2026-11-27. CISA KEV catalogVersion 2026.11.27 checked.
